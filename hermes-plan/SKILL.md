# Hermes Plan — 结构化任务规划

> *"先规划再执行，避免方向偏差。"* — Hermes Agent 设计原则

---

## 核心理念

对标 Hermes 内置 `/plan` Skill：在执行前先生成结构化的任务计划，
适合需要多步执行的复杂任务。防止 Agent 在没有规划的情况下
直接执行导致的方向偏差和返工。

Hermes 官方描述：
> "Create structured task plans before execution for multi-step tasks.
> Prevents direction drift from unplanned direct execution."

---

## 何时触发

本 Skill 应在以下场景自动触发（或通过 `/plan` 手动触发）：

- 任务涉及 **5 个以上步骤**
- 任务涉及 **多个文件/模块的修改**
- 用户明确说"先计划一下"
- 任务影响范围不明确，需要先梳理
- 用户给了模糊的大目标（"把项目部署到阿里云"）

**不触发的情况**：
- 单行代码修改
- 简单问答
- 已有明确步骤清单的任务

## 行为准则

### 1. 规划粒度

- 每个步骤应该是**可独立验证**的
- 步骤粒度控制在「一个人能在一个连续动作里完成」
- 太粗 → 拆；太细 → 合并

### 2. 验证先行

每个步骤必须带验证方法——这是 Hermes 的核心纪律：
- ❌ "修改配置文件"
- ✅ "修改配置文件 → 运行 `hermes doctor` 验证"

### 3. 可并行标记

识别可并行的步骤，用 `[可并行]` 标记：
```
├─ 步骤 2.1: [可并行] 更新前端依赖
├─ 步骤 2.2: [可并行] 更新后端依赖
```

### 4. 中断恢复

如果任务被中断（用户离开、会话超时），规划本身作为恢复点：
- 完成步骤标记 `✅`
- 当前步骤标记 `🔄`
- 失败步骤标记 `❌` + 失败原因

---

## 与 hermes-soul 协同

当 `hermes-soul` 同时激活时，规划会自动融入用户偏好：
- 用户偏好 Docker → 默认用 Docker 部署方案
- 用户偏好简洁 → 减少解释性文字
- 用户项目技术栈 → 自动匹配技术选型

## 搭配使用

- `/hermes-soul` — 人格配置，让规划风格匹配用户偏好
- `/pua` — 高压执行，确保计划每个步骤都闭环验证
- `/skill-creator` — 如果某个规划反复使用，沉淀为新 Skill
